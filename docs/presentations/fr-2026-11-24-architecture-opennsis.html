AdresseRépond

  • Une adresse et un port pour tout, donc un seul certificat et une seule règle de pare-feu.
  • Les limites sont ici : téléversements jusqu'à 1 Go, tentatives de connexion limitées en fréquence.
  • Un client ne voit jamais que la norme, pas le logiciel qui est derrière.

B · Données

Ce qui est conservé, et où

Base de données

Trois schémas : soil_data (tables ISO 28258), api (utilisateurs, réglages, journal d'audit, site web) et une zone d'attente pour les téléversements.

Rasters

Les GeoTIFF et un fichier de carte par couche, dans sis-web-services/volume.

Fiches du catalogue

Un fichier XML ISO 19139 par fiche, dans sis-metadata/volume.

Configuration

Les secrets générés à l'installation, dans .env, et les images du site dans sis-site/volume.

Les conteneurs peuvent être jetés et reconstruits à tout moment à partir du code public. Ces quatre choses, non : c'est ce que contient une sauvegarde.

C · Sécurité

La séparation est le modèle de sécurité

  • Une seule entrée. Les requêtes arrivent par nginx, sur les ports 80 et 443 ; la base de données n'a aucun port sur le serveur.
  • Le moindre privilège pour la fédération. Son API utilise un utilisateur de base de données qui ne peut lire que trois vues, et exige un jeton.
  • Lecture seule quand c'est possible. MapServer et nginx voient le dossier des rasters mais ne peuvent pas y écrire.
  • Comptes. Jetons signés pour les sessions, verrouillage après cinq échecs de connexion, et journal d'audit.
  • Secrets propres à chaque serveur. Générés à l'installation, jamais livrés avec le code.

Chaque conteneur peut faire
sa propre tâche,
et pas grand-chose d'autre.

R · Exploiter

Installer et mettre à jour : la même idée

# installer : un serveur Linux vide
curl -fsSL …/ops/single/host-install.sh \
  | sudo bash -s -- TN
# mettre à jour : à tout moment ensuite
cd /opt/sis && ./update.sh

Une seule description du système (un fichier Docker Compose) sert pour un portable, un serveur national et un hôte à plusieurs instances.

  • Installer : Docker, pare-feu, code, secrets, base de données avec les listes de codes, puis les sept conteneurs.
  • Mettre à jour : récupérer le code, appliquer les changements numérotés de la base (39 à ce jour), reconstruire les trois conteneurs applicatifs.
  • Les conteneurs de la base de données, de MapServer et du catalogue continuent de tourner ; les données ne sont jamais rechargées.
