O · Options

Three possible homes

Cloud

A virtual server rented from a private provider, paid by the month.

Government IT

A virtual server in the Government data centre or in the ministry's IT infrastructure.

In the institution

A machine in the server room of the institution itself, managed by its IT team.

OpenNSIS works the same way in all three. What changes is who looks after power, network and the bill, and who holds the key.

O · Options

Cloud: private provider

In favour

Ready in minutes, with no equipment to buy.
Power, network and hardware are the provider's problem.
Instant snapshots of the whole machine.
Predictable monthly cost; one click to grow.

To bear in mind

A recurring payment, usually in foreign currency: who pays after the project?
The data sit outside the country: check the national policy.
It depends on the international Internet link.

Order of magnitude: for the size needed, a few tens of dollars a month, depending on the provider.

O · Options

Government IT infrastructure

In favour

The data stay in the country, under public custody.
Power, network and physical security already exist.
As a rule, no direct monthly bill.
In line with the e-government strategy.

To bear in mind

Another institution's procedures and timescales.
Administration access (SSH): agree at the start who has it.
Rules on software and ports: confirm that Docker and ports 80/443 are allowed.
Who steps in out of hours?

Good practice: a written agreement between the two institutions covering resources, access, contacts and responsibilities.

O · Options

In the institution itself

In favour

Full control, with no outside dependencies.
The team sits next to the machine.
The data never leave the building.
It strengthens the institution's IT capacity.

To bear in mind

Stable power: UPS and, ideally, a generator.
Air conditioning and physical security of the room.
Internet with a fixed public IP and enough bandwidth.
Hardware ages: plan its replacement.
Someone from IT available, also during holidays.

If power or Internet fails in the building, the national SIS is off the air for the whole country.

A · Requirements

Software: three pieces, all free

Linux

The server's operating system. A version with long-term support, with kernel 4.15 or newer.

Docker

Docker Engine + Compose. Each component runs in its own container: database, API, maps, catalogue, web server.

Git

It fetches the code, and the updates, from the public repository un-fao/OpenNSIS.

Nothing else is installed on the system: PostgreSQL/PostGIS, MapServer, pyCSW and nginx come inside the containers. No licences to pay.

A · Requirements

Network, domain and HTTPS

  • A fixed public IP and ports 80 and 443 open in the firewall.
  • A domain name of the institution, with a DNS record pointing to the server.
  • Automatic HTTPS: the domain is given at installation; the certificate is obtained and renewed by itself.
  • Outbound Internet: updates (GitHub), Docker images, covariates for the sampling designs.
# language and domain set from the start
LANGUAGE=fr \
DOMAIN=soils.example.gov.tn \
sudo -E ops/single/host-install.sh TN

The domain is an example: the real name is the institution's decision.

Install · one command

From an empty server to a live SIS

1
Log in to the server by SSH.
2
Paste the installation command:
curl -fsSL https://raw.githubusercontent.com/un-fao/OpenNSIS/main/ops/single/host-install.sh | sudo bash -s -- TN
3
The installer does the rest: Docker, firewall, code in /opt/sis, database, services and the admin user.
4
Keep the administration password: it is shown only once, at the end.
The system is born empty, with only the code lists: Tunisia's data come in afterwards, through the admin panel or by restore.

Configuration.envthe secrets generated at installation
Everything else is rebuilt from the public code. These four things are what goes into the backups.

B · Install

Updating: another command

cd /opt/sis
./update.sh
  • It fetches the new code, applies the changes to the database and rebuilds only the application.
  • It never touches the data: profiles, maps and catalogue stay as they were.
  • The panel shows the installed version and whether there is anything new. It only checks.

C · Operate

Backups: two commands

# 1 · the database
docker exec sis-database pg_dump -U sis -d sis | gzip > sis-db-$(date +%F).sql.gz
# 2 · maps, catalogue and configuration
tar czf sis-volumes-$(date +%F).tgz sis-web-services/volume sis-metadata/volume .env

Off the server

A copy that stays on the same machine is not a backup.

Automatic

Scheduled on the server, and someone confirms every month that it ran.

Tested

You only know a backup is good after restoring it on a test machine.

C · Operate

Basic security

What comes already done

Secrets generated at installation, unique to each server.
Random administration password, with no default value.
Database not exposed to the Internet.
Account locked after five failed attempts.
An audit log that cannot be altered.

What falls to the institution

HTTPS with its own domain.
Firewall: only SSH, 80 and 443.
SSH access by key, with personal accounts.
Operating system kept up to date.
One account per person in the admin panel.

When someone leaves the team, their account is disabled the same day.

C · Operate

Moving home, or recovering from a disaster

1

Install

On the new server, the same installation command.

2

Copy

Take the two backups there.

3

Restore

Database, maps, catalogue and configuration.

4

Point

Change the DNS record to the new server and check.

It is the same path for going from the demonstration instance to the national server. The procedure is documented in the repository.

R · People

Two roles, and always a deputy

System administrator (IT)

Installs, updates, makes and checks the backups, watches the server.

About 4 hours a month, after a few days for the installation.

Soil data manager

Uploads profiles and maps, fills in metadata, chooses licences, maintains the website.

Continuous work, at the pace of the projects and the data.

A system that depends on one person stops when that person goes on holiday, falls ill or changes job. Two names per role.

R · People

Decisions to take away

  • Which of the three homes, and who signs the agreement?
  • Who pays, and from which budget, when the project ends?
  • Who is the administrator and who is the deputy?
  • Which domain will the national SIS have?
  • Where are the backups kept?
  • Who do we ask for technical support?
