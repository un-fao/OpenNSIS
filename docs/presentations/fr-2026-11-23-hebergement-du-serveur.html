O · Options

Trois maisons possibles

Cloud

Un serveur virtuel loué à un fournisseur privé, payé au mois.

Informatique de l'État

Un serveur virtuel dans le centre de données du Gouvernement ou dans l'infrastructure informatique du ministère.

Dans l'institution

Une machine dans la salle des serveurs de l'institution elle-même, gérée par son équipe informatique.

OpenNSIS fonctionne de la même façon dans les trois. Ce qui change, c'est qui s'occupe de l'électricité, du réseau et de la facture, et qui détient la clé.

O · Options

Cloud : fournisseur privé

Pour

Prêt en quelques minutes, sans achat de matériel.
Électricité, réseau et matériel sont le problème du fournisseur.
Instantanés de la machine entière.
Coût mensuel prévisible ; un clic pour grandir.

À garder à l'esprit

Un paiement récurrent, en général en devises : qui paie après le projet ?
Les données sont hors du pays : vérifier la politique nationale.
Dépend de la liaison Internet internationale.

Ordre de grandeur : pour la taille nécessaire, quelques dizaines de dollars par mois, selon le fournisseur.

O · Options

Infrastructure informatique de l'État

Pour

Les données restent dans le pays, sous tutelle publique.
Électricité, réseau et sécurité physique existent déjà.
En général, pas de facture mensuelle directe.
Conforme à la stratégie d'administration électronique.

À garder à l'esprit

Les procédures et les délais d'une autre institution.
Accès d'administration (SSH) : convenir dès le départ de qui l'a.
Règles sur les logiciels et les ports : confirmer que Docker et les ports 80/443 sont autorisés.
Qui intervient en dehors des heures de bureau ?

Bonne pratique : un accord écrit entre les deux institutions, couvrant ressources, accès, contacts et responsabilités.

O · Options

Dans l'institution elle-même

Pour

Contrôle total, sans dépendance extérieure.
L'équipe est à côté de la machine.
Les données ne quittent jamais le bâtiment.
Renforce la capacité informatique de l'institution.

À garder à l'esprit

Électricité stable : onduleur et, idéalement, groupe électrogène.
Climatisation et sécurité physique de la salle.
Internet avec une IP publique fixe et un débit suffisant.
Le matériel vieillit : prévoir son remplacement.
Un informaticien disponible, aussi pendant les congés.

Si l'électricité ou Internet tombe dans le bâtiment, le SIS national est hors service pour tout le pays.

Un SIS national est petit : il tient à l'aise sur une machine modeste. Ubuntu 26.04 LTS · Docker 29 · Git.

A · Exigences

Logiciels : trois pièces, toutes libres

Linux

Le système d'exploitation du serveur. Une version avec support à long terme, avec un noyau 4.15 ou plus récent.

Docker

Docker Engine + Compose. Chaque composant tourne dans son conteneur : base de données, API, cartes, catalogue, serveur web.

Git

Il récupère le code, et les mises à jour, depuis le dépôt public un-fao/OpenNSIS.

Rien d'autre n'est installé sur le système : PostgreSQL/PostGIS, MapServer, pyCSW et nginx sont dans les conteneurs. Aucune licence à payer.

A · Exigences

Réseau, domaine et HTTPS

  • Une IP publique fixe et les ports 80 et 443 ouverts dans le pare-feu.
  • Un nom de domaine de l'institution, avec un enregistrement DNS pointant vers le serveur.
  • HTTPS automatique : le domaine est indiqué à l'installation ; le certificat est obtenu et renouvelé tout seul.
  • Sortie vers Internet : mises à jour (GitHub), images Docker, covariables pour les plans d'échantillonnage.
# langue et domaine fixés dès le départ
LANGUAGE=fr \
DOMAIN=sols.exemple.gov.tn \
sudo -E ops/single/host-install.sh TN

Le domaine est un exemple : le vrai nom est une décision de l'institution.

Installer · une commande

Du serveur vide au SIS en ligne

1
Se connecter au serveur par SSH.
2
Coller la commande d'installation :
curl -fsSL https://raw.githubusercontent.com/un-fao/OpenNSIS/main/ops/single/host-install.sh | sudo bash -s -- TN
3
L'installateur fait le reste : Docker, pare-feu, code dans /opt/sis, base de données, services et utilisateur admin.
4
Conserver le mot de passe d'administration : il n'est affiché qu'une fois, à la fin.
Le système naît vide, avec les seules listes de codes : les données de la Tunisie entrent ensuite, par le panneau d'administration ou par restauration.

B · Installer

Mettre à jour : une autre commande

cd /opt/sis
./update.sh
  • Elle récupère le nouveau code, applique les changements à la base de données et ne reconstruit que l'application.
  • Elle ne touche jamais aux données : profils, cartes et catalogue restent tels quels.
  • Le panneau affiche la version installée et s'il y a du nouveau. Il ne fait que vérifier.

C · Exploiter

Sauvegardes : deux commandes

# 1 · la base de données
docker exec sis-database pg_dump -U sis -d sis | gzip > sis-db-$(date +%F).sql.gz
# 2 · cartes, catalogue et configuration
tar czf sis-volumes-$(date +%F).tgz sis-web-services/volume sis-metadata/volume .env

Hors du serveur

Une copie qui reste sur la même machine n'est pas une sauvegarde.

Automatique

Planifiée sur le serveur, et quelqu'un confirme chaque mois qu'elle a été faite.

Testée

On ne sait qu'une sauvegarde est bonne qu'après l'avoir restaurée sur une machine de test.

C · Exploiter

Sécurité de base

Ce qui est déjà fait

Secrets générés à l'installation, propres à chaque serveur.
Mot de passe d'administration aléatoire, sans valeur par défaut.
Base de données non exposée à Internet.
Compte verrouillé après cinq tentatives échouées.
Un journal d'audit qui ne peut pas être modifié.

Ce qui revient à l'institution

HTTPS avec son propre domaine.
Pare-feu : seulement SSH, 80 et 443.
Accès SSH par clé, avec des comptes personnels.
Système d'exploitation tenu à jour.
Un compte par personne dans le panneau d'administration.

Quand quelqu'un quitte l'équipe, son compte est désactivé le jour même.

1

Installer

2

Copier

Y apporter les deux sauvegardes.

3

Restaurer

Base de données, cartes, catalogue et configuration.

4

Pointer

Changer l'enregistrement DNS vers le nouveau serveur et vérifier.

C'est le même chemin pour passer de l'instance de démonstration au serveur national. La procédure est documentée dans le dépôt.

R · Personnes

Deux rôles, et toujours un suppléant

Administrateur système (informatique)

Installe, met à jour, fait et vérifie les sauvegardes, surveille le serveur.

Environ 4 heures par mois, après quelques jours pour l'installation.

Gestionnaire des données de sol

Charge les profils et les cartes, remplit les métadonnées, choisit les licences, tient le site web.

Travail continu, au rythme des projets et des données.

Un système qui dépend d'une seule personne s'arrête quand elle part en congé, tombe malade ou change d'emploi. Deux noms par rôle.
