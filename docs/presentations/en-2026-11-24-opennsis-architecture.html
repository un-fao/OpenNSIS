Blue boxes speak an open standard to the outside world. Everything runs as Docker containers on one Linux server.

  • One address and one port for everything, so one certificate and one firewall rule.
  • The limits live here: uploads up to 1 GB, sign-in attempts rate-limited.
  • A client only ever sees the standard, never the software behind it.

B · Data

What is kept, and where

Database

Three schemas: soil_data (ISO 28258 tables), api (users, settings, audit log, website) and a staging area for uploads.

Rasters

The GeoTIFFs and one map file per layer, in sis-web-services/volume.

Catalogue records

One ISO 19139 XML file per record, in sis-metadata/volume.

Configuration

The secrets generated at installation, in .env, and the website images in sis-site/volume.

The containers can be thrown away and rebuilt from the public code at any time. These four things cannot: they are what a backup holds.

C · Security

Separation is the security model

  • One way in. Requests arrive through nginx, on ports 80 and 443; the database has no port on the server at all.
  • Least privilege for the federation. Its API uses a database user that can read three views and nothing else, and asks for a token.
  • Read-only where possible. MapServer and nginx see the raster folder but cannot write to it.
  • Accounts. Signed tokens for sessions, a lock after five failed sign-ins, and an audit log.
  • Secrets per server. Generated at installation, never shipped in the code.

Each container can do
its own job,
and little else.

R · Operate

Installing and updating are the same idea

# install: an empty Linux server
curl -fsSL …/ops/single/host-install.sh \
  | sudo bash -s -- TN
# update: any time later
cd /opt/sis && ./update.sh

One description of the system (a Docker Compose file) serves a laptop, a national server and a host with many instances.

  • Install: Docker, firewall, code, secrets, database with the code lists, then the seven containers.
  • Update: fetch the code, apply the numbered database changes (39 so far), rebuild the three application containers.
  • The database, MapServer and catalogue containers keep running; the data are never reloaded.
