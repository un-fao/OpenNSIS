O · OGC

OGC: agreeing on a common language

  • The Open Geospatial Consortium — an international, member-driven body where public agencies, software makers and researchers agree on open standards for geographic information.
  • It works hand in hand with ISO/TC 211 — so OGC service standards and ISO data standards form one family.
  • A standard is a public rulebook: anyone may implement it, in any software, without permission or fees.
  • Everything in this talk — describing data, serving maps, searching catalogues, federating countries — exists as one of these standards.

A · Spatial metadata

What is it

Metadata is structured information about a dataset — everything you need to know before you trust it.

  • Identification — what is measured, where, when, by whom
  • Spatial reference — coordinate system, resolution, extent
  • Method & lineage — how values were produced, from which sources
  • Terms — licence, constraints, contact for questions

A · Spatial metadata

Why it matters

  • Findability — a dataset nobody can discover might as well not exist.
  • Fitness for use — is a 250 m map from 2009 good enough for a 2026 field decision? Only metadata can tell you.
  • Institutional memory — staff move on; well-described data outlives the person who made it.
  • No duplicated effort — surveys are expensive; knowing what exists prevents paying for it twice.
  • Legal clarity — licence and constraints are part of the record, not folklore.

A · Spatial metadata

What exists for it

A standard

ISO 19115 defines which fields describe geographic data; ISO 19139 defines the XML that carries them. One shared vocabulary worldwide.

Catalogues

Software that stores records and answers searches: pyCSW, GeoNetwork. Regional frameworks such as INSPIRE make publishing them a legal duty in Europe.

In OpenNSIS

The ISO 19115 record is generated automatically from the form you fill when registering a mapset — and published in the built-in catalogue. No XML editing, ever.

The metadata form and the catalogue are two views of the same database record.

B · Web services

What is it

  • Data offered over HTTP by agreed rules: a fixed way to ask, a fixed way to answer — defined by the OGC standards.
  • The client never needs to know what software sits behind the URL — only the standard.
  • Instead of e-mailing files, you share a living endpoint: always the current version, straight from the source.
http://5.223.62.255:8024/mapserver?
  map=/etc/mapserver/US-KANSAS-CARORG-2026-0-30-MEAN.map

The service family

ServiceYou ask for…You get back…

WMTSpre-cut map tilesfast tiles for web viewers
WFSthe features themselvesvector data — points, polygons, attributes
WCSthe raw gridraster values you can compute on

Rule of thumb: WMS to look, WFS/WCS to analyse, CSW to find.

B · Web services

Why it matters: publish once, use anywhere

  • Interoperability — the same WMS layer opens in QGIS, ArcGIS, a web page and a Python script, unchanged.
  • No vendor lock-in — swap the server software; every client keeps working, because the interface is the standard, not the product.
  • One authoritative source — colleagues consume the service instead of e-mailing copies that immediately go stale.
  • Federation-ready — systems that speak the same standards can be connected later without redesign.

B · Web services

What exists for it

Servers

MapServer and GeoServer publish WMS/WFS/WCS; pyCSW publishes the catalogue. All free and open source, all battle-tested for decades.

Clients

Every serious GIS speaks OGC out of the box — desktop (QGIS, ArcGIS), web libraries (OpenLayers, Leaflet), and scripting (Python owslib, R).

In OpenNSIS

Every published raster is automatically a WMS layer (MapServer), and every metadata record is served by CSW (pyCSW) — the standards run quietly underneath.

The map you saw in the browser is itself a WMS client — eating the system's own service.

C · GloSIS

GloSIS: a federation, not a warehouse

  • The Global Soil Information System of the FAO Global Soil Partnership.
  • Not one central database: a network of national systems that stay on national servers, under national mandate.
  • Each country exposes its soil data through standard interfaces; the global level connects to them.
  • Data sovereignty is the design, not an afterthought — countries decide what is shared, and keep the original.

C · GloSIS

The common language of soil data

  • Harmonised codelists — one agreed identifier per soil property and per laboratory procedure, drawn from the GloSIS web ontology.
  • “pH in water, 1:2.5” means exactly the same thing in Colombo, Bishkek and Rome — so values become comparable, not just collectable.
  • Global products such as GSOCmap are compiled from national data — quality at the national level is what the world ends up seeing.
  • A national system that speaks GloSIS is born connected: no conversion project later.
# the same measurement, everywhere
property:  phH2o
procedure: phH2o-1:2.5
unit:      pH

R · OpenNSIS

OpenNSIS: the bedrock

  • An Open-source National Soil Information System, developed by FAO for — and with — national soil institutions.
  • Apache 2.0 licence: the code, database schema, deployment scripts and documentation are public. No handover needed — it is already yours.
  • Installs on an ordinary Linux server with one command; updates with one more.
